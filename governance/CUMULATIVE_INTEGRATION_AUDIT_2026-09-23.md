## 1. Integration rule

The repository is now explicitly treated as **cumulative**:

`Field Notes / engineering → Foundation → Principles → Requirements → Architecture → validation/scenarios → benchmark/test → Positioning/RA/MSCA → application packages`.

An older document may remain technically valuable while not reflecting later architecture. The correct treatment is:

- preserve the older text;
- identify its date/status/scope;
- link the later development;
- do not silently rewrite a frozen source;
- do not imply that a later concept was already present in an earlier test or benchmark;
- introduce any new normative requirement through an explicit versioned change.
