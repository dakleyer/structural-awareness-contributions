# Ecosystem Awareness — public entry point

The **complete Ecosystem Awareness corpus** is in one [canonical reading folder](./baseline/README.md). Its index explains the problem, the present six-document argument, the candidate extension annexes, validation profiles, five research-lineage articles, controls and provenance. Start there; this page is only the route from the wider repository.

For a problem-to-architecture reading route, begin with the [EA foundation](./baseline/01_FOUNDATIONAL_THEORY_v0.5_INTEGRATED.md), then the [EA principles](./baseline/02_EPISTEMIC_SAFETY_PRINCIPLES_CONTROL_MATRIX_v0.4.part01.md), then [00 — Canonical Requirements: Challenges, Sufficiency Conditions, Hypotheses and KPIs](./baseline/00_CANONICAL_REQUIREMENTS_CHALLENGES_SUFFICIENCY_HYPOTHESES_KPIS.md), then the [100-million-token enterprise reference failure scenario](./baseline/00E_FAILURE_MODES_100M_TOKEN_COMPOUNDING_v0.1.md), the [smart-city mobility reference failure scenario](./baseline/00F_FAILURE_MODE_SMART_CITY_MOBILITY_SYSTEMIC_DIVERGENCE_v0.1.md), the [concrete EA architecture](./baseline/00_CANONICAL_ARCHITECTURE_TOPOLOGY.md), and finally the [canonical architecture benchmark and reference-scenario evidence](./baseline/00D_CANONICAL_ARCHITECTURE_BENCHMARK_AND_REFERENCE_SCENARIO_EVIDENCE_v0.2.md). The requirements document contains S1–S14, T1–T4, H1–H6 and their KPI/falsification protocol in one sequence. The two reference scenarios apply that same route to different conditions: 00E traces four coupled enterprise subsystems; 00F traces residual uncertainty and locally understandable but incompatible Emergency A, Emergency B, NORMAL and HOLD postures in a shared mobility corridor. The 00E product annexes apply its tests to [Microsoft Agent 365](./baseline/00E_A01_MICROSOFT_AGENT_365_IMPLEMENTATION_PROFILE_v0.1.md) and [LangGraph/LangSmith](./baseline/00E_A02_LANGGRAPH_LANGSMITH_IMPLEMENTATION_PROFILE_v0.1.md); the 00F annexes apply the mobility test to [FIWARE NGSI-LD / Orion-LD](./baseline/00F_A01_FIWARE_NGSI_LD_IMPLEMENTATION_PROFILE_v0.1.md) and [AWS IoT TwinMaker / IoT Core](./baseline/00F_A02_AWS_IOT_TWINMAKER_CORE_IMPLEMENTATION_PROFILE_v0.1.md). Each includes a strong implementation under regime change and none is a product benchmark. The single canonical benchmark integrates EA-H1–EA-H4, fair B0–B3 comparison and primary-source corroboration of the mechanisms in both scenarios; it does not prove EA or turn the fictional cases into historical incidents.

EA asks whether the evidence, residual uncertainty, assumptions and response capacity supporting **a particular decision** remain sufficient when its ecosystem is partly known and changing. It does not assume that local correctness, more agents, or a human approval necessarily settles the whole decision. Its candidate contribution is scoped epistemic qualification and proportionate requalification, to be tested against strong neighbouring architectures.
