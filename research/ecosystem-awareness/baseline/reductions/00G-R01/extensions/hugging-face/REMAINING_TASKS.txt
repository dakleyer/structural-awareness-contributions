PURPOSE AND STATUS
Complete the missing bridge from the constructed HF-compatible scenario to
three identified executable technology configurations. Scenario-to-scenario
transfer already has a conditional proposition and finite witnesses within
their stated scope. It does not automatically admit a particular runtime,
model, integration or historical incident.

Here "Hugging Face" names the constructed case family in this repository.
It does not require every candidate to be hosted on the HF Hub, and it does
not claim these frameworks were responsible for the reported incident.

This file plans three integrations and their tests; none was implemented or
run by this documentation update. Preserve favorable, unfavorable, blocked
and inconclusive findings. A successful defense is a valid outcome.

THREE CANDIDATES TO QUALIFY
1. Hugging Face smolagents
   Candidate role: model-driven receiver using controlled tools.
   Start by assessing ToolCallingAgent; CodeAgent is a distinct profile if
   its execution surface is needed. Official documentation describes both.
   Check tool effects, step/memory capture, instruction boundaries and
   whether code execution adds undeclared operations or information.
   Source: https://huggingface.co/docs/smolagents/index

2. LangGraph
   Candidate role: explicit stateful execution of search, review, message
   receipt and decision stages. Official documentation describes graph
   orchestration, persistence and deterministic/model-driven steps.
   Check checkpoint/replay semantics, duplicate effects, observation
   isolation and accounting for resumed work. Persistence grants no
   authority and certifies no evidence by itself.
   Source: https://docs.langchain.com/oss/python/langgraph/overview

3. OpenAI Agents SDK (Python)
   Candidate role: receiver integration with tool execution and trace
   instrumentation. Official tracing documentation describes generations,
   tool calls, handoffs and guardrail events.
   Check whether trace hooks expose every required commitment, attempt and
   effect; add environment-owned receipts where SDK traces are insufficient.
   SDK traces alone do not prove permission or legitimate completion.
   Source: https://openai.github.io/openai-agents-python/tracing/
   Repository: https://github.com/openai/openai-agents-python

COMMON ADAPTER CONTRACT
Input: a registered world reference, assignment, agent-visible initial
observations, permitted tools, budget, deadline and policy configuration.
Output: append-only recorder events and raw outputs with IDs, timestamps,
versions, declared scope, provenance, usage, costs and disposition.

The environment owns permissions and actual-effect receipts. The evaluator
owns the hidden full map, I/P labels and ground-truth verdicts. Native
runtime controls remain enabled and documented. Do not remove a defense
merely to obtain a negative result.

Use controlled replicas of tools/resources in this constructed scenario.
Record the deployment boundary and every external dependency. Offline
scripted-model checks establish adapter plumbing only; a model-driven run
needs its own registration and cannot inherit an autonomous-behavior claim
from a fixture.

TRANSFER EVIDENCE REQUIRED PER TECHNOLOGY
E1: map every material object, relation and operation.
E2: map enabled events, attempts, effects and stopping conditions.
E3: preserve the claimed transition law, or explicitly reject exact transfer.
E4: match observations and the stated policy correspondence/class; no leak.
E5: account for all work, elapsed time and normalized resources.
E6: preserve admissibility, quality and outcome semantics.
E7: cover declared trajectories, legitimate alternatives and incompleteness.

An adapter that records matching fields does not establish E1–E7. If a
model's stochastic policy differs, scenario execution may still be useful
but numerical outcomes do not transfer from another policy automatically.
If the mathematical result quantifies over all observation-based policies
of a class, show that this implementation belongs to that class. If it
concerns paired policies, verify the pairing instead.

For approximate transfer, state an independently justified error bound and
how it affects the feasibility threshold. Do not invent a tolerance after
seeing the result. If no correspondence is defensible, mark the integration
outside theorem scope while retaining its experiment as separately defined.
