  1. Purpose, scope and status
  On the documentation read, the three frameworks act on the risk arm through pre-effect
  barriers and on the cost arm through constants, but none supplies what sets the tier: a
  verification interface that returns many bits of binding information per unit cost. That
  interface belongs to the environment, not to the framework. This annex works that
  conclusion out, mechanism by mechanism, and lists what must be measured to confirm or
  refute it.

  What this annex is. An annex to R01 Viability as a Trilemma: Proof Sketches and Review
  Plan. It reuses that document's definitions, Lemma 1 and the tier table, and applies them
  to the three configurations that task T01 asks to qualify: Hugging Face smolagents,
  LangGraph (with LangSmith for tracing) and the OpenAI Agents SDK for Python. Each is
  read in its official documentation, opened on 4 October 2026.

  What it is not.

         It is not an execution. Nothing here was run, installed or measured, and versions are
         not pinned.
         It is not a comparison of quality or safety between the frameworks, and it makes no
         claim about EA.
         It is not an admission decision. T02, T07 and T11 decide admission on evidence gathered
         against pinned versions.
         It does not cover the other technologies profiled elsewhere in the corpus (Microsoft
         Agent 365, Claude Agent SDK, FIWARE and others).

  Second reading. A second pass on 4 October 2026 closed most of the U labels in sections
  4 to 6 and surfaced new hazards. Everything below is in the tables of those sections.

         smolagents step callbacks are not a barrier. The project blog states that step
         callbacks run at the end of each step, after the action has executed. The wrapper
         around the tools is therefore the only pre-effect barrier found (D).
         LangGraph's exit durability can lose progress. In exit mode state is persisted only
         when execution exits or at an interrupt. A crash mid-run then restarts from the last
         exit, and effects since then repeat unless they sit inside tasks (D, I).
         LangGraph's RunControl is a cooperative stop. It drains at a superstep boundary, so a
         deadline can be enforced between steps and not inside a long node. recursion_limit
         counts supersteps, not cost (D).
         OpenAI sandbox agents allow rollback of confined effects only. Snapshots restore
         the workspace, but they skip mounted remote storage, and the manifest describes
         only a fresh session, so live state can differ from it. That gap is a staleness hazard of
         the kind in section 9, and the receipts must record the effective state, not the manifest
         (D, I).
         OpenAI's max_turns counts model turns. Its numeric default was not visible in the
         excerpts read.

  Position in the gate. The R01 contract fixes the order review, decide, execute, with a
  receipt visible only after the effect. Every mechanism is placed in one of four positions:
  before the decision, between decision and execution, at execution, or after the receipt. A
  barrier is only a barrier in the second position. The same check placed after the receipt is
  an observation.

  The tier question. The tier is set by f(b), the cost of settling b independent bits. A
  verification interface has two properties that matter: bits returned per call, and cost per
  call. Three interface shapes recur.

  A deterministic code check and a model-based check can have the same capacity and
  very different cost per call. The capacity decides the tier and the cost per call decides the
  constant.

  Two attribution rules. They exist to stop a mechanism being credited with something it
  cannot do.

   1. Source rule. A mechanism that decides using information must name the source of
       that information. If the source is the model's own estimate of the binding, it adds no
       information. By Lemma 1 it can only reshuffle risk and add cost. A guardrail model that
       does not read the environment's binding facts gives the same prior as the agent.
   2. Coverage rule. A barrier credited with lowering risk must be shown to act before the
      effect on every effectful tool in the stack. One unguarded effect path voids the claim
       for that path.

  4. smolagents
  On the pages read, smolagents has no framework-level pre-effect gate in its core loop, so
  the barrier has to be an environment-owned wrapper around the tools. Its distinctive
  effect on the trilemma is batching: code actions and parallel tool calls let several effects
  occur between model decisions, which lowers cost and removes the intermediate
  receipts that a gate relies on.

  Profile (D). smolagents is a library for multi-step agents that follow a ReAct loop of
  thought, tool call, observation. It offers two agent types: CodeAgent , which writes its tool
  calls as Python code and is the default, and ToolCallingAgent , which writes them as
  JSON. The reference describes the API as experimental. The R01 plan asks T01 to assess
  ToolCallingAgent first and to treat CodeAgent as a distinct profile if its execution
  surface is needed.

  Where the barrier lives. Tools are plain callables (I), so the natural pre-effect barrier is a
  wrapper owned by the environment, which is what the R01 adapter contract already asks
  for under the name controlled tool wrappers. That wrapper is also where binding
  information enters, through a call to whatever registry the environment exposes. The tier
  of a smolagents configuration is therefore the tier of the wrapper's verification interface.
  smolagents itself neither raises nor lowers it.




                                                                                                                                Page 11 of 38

  Batching and the slack threshold. Let m be the number of effects executed per model
  decision. With m above 1 the policy cannot read a receipt between effects, so inside a
  block it behaves like the blind policy. At the same time the model-request share of the
  gate falls from about g to about g/m, which lowers g. Because the threshold slack is
  lambda* = c(1 - alpha)/g, a smaller g raises lambda*. The consequence is counter-intuitive
  and testable: cheaper execution widens the relative trilemma band, because information
  becomes relatively more expensive.

  Sandboxing and the irreversible-violation assumption. Assumption A4 says a violation is
  permanent. A sandbox changes that only if the effect itself lands inside the sandbox and
  is committed to the outside world by a separate step the environment can veto. A route-
  level dry run of this kind returns per-node activity for the whole route, so its capacity is L
  bits per call. Its cost, however, grows with route length, because executing L nodes in the
  sandbox costs about L times the dry-run cost per node. That is Tier 3 with a small
  constant, not Tier 1. If the effect tools stay outside the sandbox, nothing changes.

  Plan review and final-answer checks. A human reviewing a plan supplies information only
  if the reviewer knows the binding, and each review costs minutes. The documented
  interface of three choices carries at most log2(3) bits per review, although modification of
  the plan can carry more if the reviewer knows more. A final-answer check cannot lower
  risk because it runs after the effects. Rejection of an incomplete answer also consumes
  steps from max_steps, so it trades cost for efficacy.

  What T02 and T07 must settle for smolagents.

   1. Confirm with X7 that a step callback cannot veto the tool call of its own step, as the
       project blog states that callbacks run at the end of each step (D).
   2. Effects executed per decision step for CodeAgent and for ToolCallingAgent with
       parallel threads, counted from environment receipts (D, I).
   3. Where tools execute under each remote executor, and whether their effects can be
      discarded (I).
   4. What interrupt() does and when (U).
   5. What the telemetry tutorial exposes and whether it is complete (U).


  5. LangGraph and LangSmith
  LangGraph is the configuration whose structure maps most directly onto the R01 gate,
  because review, decision and execution can be separate nodes with the decision as an
  edge. Its main effect on the trilemma is in replay: pauses and resumes re-run code, so the



                                                                                           Page 12 of 38

  same machinery that gives a barrier can duplicate effects if the effect sits on the wrong
  side of a pause.

  Profile (D). LangGraph is a low-level orchestration framework and runtime for long-
  running, stateful agents. It lets a graph mix deterministic, hand-coded steps with model-
  driven steps. Persistence, durable execution, streaming and human-in-the-loop are its
  stated core capabilities. LangSmith is the separate platform for tracing and evaluation.
  The R01 plan asks T01 to check checkpoint and replay semantics, duplicate effects,
  observation isolation and accounting for resumed work, and states that persistence
  grants no authority and certifies no evidence by itself.

  Structure gives a native barrier; it does not give information. A graph can route every
  effect through a review node and an edge, and then the effect node cannot run unless the
  edge allows it. What the review node knows is whatever it can read. If it reads a registry
  that answers per node, the interface is a per-bit probe and the tier is 3 with a small
  constant. If it reads a map certificate in one call, the interface is Tier 1. LangGraph
  supports both and chooses neither.

  Replay as a risk mechanism. Every approval is a resume, and every resume restarts the
  node. If a non-idempotent effect sits earlier in the same node than the interrupt, each
  resume repeats it. The effects then multiply with the number of approvals, each one costs
  g again, and a violating effect is repeated while the violation counter stays at one. The
  documentation describes the replay of a loop of interrupts as growing with each resume,




                                                                                                                              Page 16 of 38
R01 Annex T — How Concrete Agent Technologies Act on the Trilemma




  because the first resume replays one iteration, the second two, and so on. The design
  consequence is that the interrupt must come before the effect and the effect must sit in
  its own node.

  Human approval is a one-bit probe behind a barrier. An approve-or-reject interrupt on a
  route is a membership test returning at most one bit per decision. Because rejection
  prevents the effect, it is risk-free. That is the Tier 3' shape of the first document, with c
  equal to the cost of one human decision, in minutes and in deadline. The wait has no
  stated limit, so it consumes the R01 deadline T as well as budget.

  Durability modes and the recorder. In sync mode every checkpoint is written before
  execution continues, which costs time. In async mode a crash can lose a checkpoint, and
  after resume the node may run again although its effect already happened. A checkpoint
  is therefore not a receipt. The environment must own the append-only record of effects,
  as the R01 adapter contract requires, and the checkpointer can only be compared against
  it.

  LangSmith. Tracing is an observation channel. The Engine, which detects issues in traces
  and proposes fixes, acts on later runs. It does not change the risk of the run in which an
  effect has already happened. Its relevance is to drift and to measurement, not to the arms
  of a single run.

  What T02 and T07 must settle for LangGraph.

   1. Count effects per route under resume in each durability mode, with and without tasks
      around the effect.
   2. Test approval-to-interrupt matching when node code is non-deterministic.
   3. Test whether a static interrupt placed before the effect node is a reliable barrier, and
      whether it survives replay.
   4. Confirm that RunControl stops a run only at a superstep boundary, and read the time-
      travel semantics, which this annex knows only from a secondary source that describes
      replay as re-executing the nodes after a checkpoint.
   5. Compare the cost of a graph step with the cost reported by LangSmith, so E5
      accounting is complete.

  The barrier is conditional. Three configurations act before the effect: a tool input
  guardrail on a covered tool, a blocking input guardrail, and an approval requirement. The
  default parallel input guardrail does not, by the documentation's own statement. Any
  hosted or built-in execution tool bypasses the guardrail pipeline. The coverage rule of
  section 2 therefore applies directly: an R01 effect must be a function tool, or a local MCP
  tool with guardrails configured, otherwise the barrier claim is void for it. The R01 contract
  keeps native defenses enabled, so default and blocking modes must be registered as
  separate configurations. Otherwise the phrase native defenses names two different
  systems.

  Where information enters. A guardrail function is ordinary code, so it can read a registry
  and decide deterministically at a cost of compute. It can also call a model. The source rule
  decides the value of either. A model guardrail that cannot read the environment's binding
  facts adds a model request and no information. A guardrail that reads the registry returns
  exactly what the registry's interface returns.




                                                                                                                                            Page 21 of 38
R01 Annex T — How Concrete Agent Technologies Act on the Trilemma




  Rejection-based probing and the width of the band. When a barrier rejects a call, the
  agent learns one bit and must try again. Each rejected attempt costs a model request and
  a guardrail evaluation, call it a. A blind policy under a barrier tries x on a layer, is refused if
  the binding is y, and tries y. In the worst case it pays two attempts per layer, so the budget
  needed is about twice R_exec, with risk zero and efficacy one. In the notation of the first
  document this is Tier 3' with f(b) = a b. If a is of the order of one model request and g is of
  the same order, the threshold slack is:

     \lambda^{*}=\frac{a\,(1-\alpha)}{g}\;\approx\;1-\alpha


  The trilemma band then extends to budgets close to twice the execution budget. This is a
  derived consequence (I) resting on a being about g, and it is the first number that T05 and
  T06 should measure, because it says that a barrier alone does not buy cheap safety. A
  band much narrower than 1 would need a to be much smaller than a model request, which
  means checks that are not preceded by a model decision, such as a route-level validator in
  code.

  Approvals and the sticky-decision hazard. needs_approval with a callback is a one-bit
  probe behind a barrier, in the same way as a LangGraph interrupt, with c equal to a human
  decision or a code decision. The sticky option is different in kind. A persisted decision for
  a tool identity approves later calls to the same tool whatever their arguments. In the R01
  fixture the effect tool is the same function for every node, so one sticky approval would
  approve every later node whatever its binding. A certificate must be scoped to the node
  and to the binding version. A sticky approval is scoped to neither unless the tool identity
  itself encodes the node.

  Recorder and resume. Traces are batched, can be dropped when export fails, are
  unavailable under zero data retention, and may omit inputs and outputs when sensitive-
  data capture is off. They are an observation of the run, not the record of effects. On
  resume, the documentation itself places on the application the duty to reconcile tool side
  effects before retrying, which is the same duplicate-effect problem as in LangGraph.

   2. The pipeline coverage of every effect tool in the fixture, by tool type.
   3. Whether guardrail model calls appear in the main run's usage (U).
   4. Whether a sticky approval carries across nodes with different bindings.

  9. Composition, units and staleness
  A stack of mechanisms reaches Tier 1 only if one component supplies a one-call map
  certificate and the stack keeps it fresh, and staleness turns the saving back into a per-
  effect cost whenever the binding can change between the certificate and the effect. Two
  further results sit beside it: the tier is stated per cost dimension, and one code-acting
  configuration can move probing from tokens to compute.

  Stacks are not additive. Each component acts on one channel of section 2. A composite
  stack pays the sum of its components' costs, and its tier is the tier of the interface that
  actually delivers the bits. A barrier, a replay control and a recorder add constants and
  safety. They do not change the growth of f(b).

  Cost is a vector, and the tier is per dimension. The R01 contract asks for normalized
  resources and forbids silent collapse to one unit. A technology can move bits from an
  expensive dimension to a cheap one without changing the tier in the cheap one.

       In a code-acting agent with an environment wrapper that raises an exception when the
       barrier refuses, the probing loop can run in code. The model writes the loop once,
       inside one decision step, and each refused attempt costs a tool call in compute and
       time, not a model request (I).
       Information is then still a per-bit probe, so f(b) is linear in compute and time. In tokens
       it is nearly flat, because the model wrote one loop.
       The trilemma band therefore persists in the dimensions where probing stays linear:
       compute, latency, registry rate limits and quotas. Whether it matters depends on the
       weights of the normalization. This is a testable effect of CodeAgent , and it is the
       strongest case in this annex of a technology helping without removing the trilemma.

  Staleness: the cost of keeping a certificate valid (sketch). Take the map certificate of
  Tier 1. Suppose that between one effect step and the next, the binding of an upcoming
  layer changes with probability p, independently. If the certificate is refreshed every k + 1
  effects, then to first order in p the expected number of stale effects is p L (k + 1)/2.
  Keeping the risk ceiling r then requires:

     \mathbb{E}[\text{stale effects}]\;\approx\;\frac{pL(k+1)}{2}\;\le\;r
     \quad\Longrightarrow\quad
     \#\text{refreshes}\;\approx\;\frac{L}
     {k+1}\;\approx\;\min\!\Big(L,\;\frac{pL^{2}}{2r}\Big)

R01 Annex T — How Concrete Agent Technologies Act on the Trilemma




  Three readings follow. If the total drift expected over the route is below the ceiling, that is
  pL of at most about r, one certificate suffices and the tier is 1. If it is above, the number of
  refreshes grows quadratically in L until it saturates at one per effect, which is the per-bit
  linear cost of Tier 3 with c equal to a refresh. Between the two, the stack is Tier 1 only in a
  regime that depends on the drift rate. The corpus's scenario 00I, in which a delayed action
  executes after a later repair has changed its decision basis, is the known case of this
  hazard. The sketch ignores the window between a check and its effect, which is the same
  hazard at a smaller scale and must be measured.

  Tier-estimation protocol for X11. For each stack and each cost dimension, fix before any
  run the grid of L, the number of replicates, the seeds, the thresholds e, r and epsilon, the
  exclusion and retry rules and the models and policies, matched across frameworks where
  possible. Measure the overhead R*(L) minus R_exec(L). Fit constant, logarithmic and
  linear models and classify by a pre-registered margin. A classification holds for the tested
  range only. With L up to 32 the experiment can separate a constant from a linear overhead
  when the per-bit cost is not negligible, and it cannot separate a logarithmic from a linear
  one. A stack that cannot be separated is reported as not distinguishable in the range, and
  no asymptotic claim is made.
