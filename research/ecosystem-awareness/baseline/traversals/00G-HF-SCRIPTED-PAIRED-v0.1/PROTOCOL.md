# 00G-HF — integrated scripted native / native+EA comparison v0.1

Author development experiment, 1 October 2026. This is the paired **programmed** traversal requested by the user, independent of a model connection. It does not satisfy the decision-open rule of empirical E1/E3 and is not a model experiment, independent validation, reserved test or historical reconstruction. This protocol, worlds, policy and harness are frozen and published before the registered execution. The author knows the fixtures and expected properties.

## Question and unit

Can a complete fixed policy acquire the allowed evidence, decide, commit, inspect and submit the legitimate result under the same environment without EA and with the published EA component integrated into its decision path? What additional cost or outcome difference appears? The experiment can support a conditional executable mechanism and reveal insufficiency, not establish that an autonomous model adopts the policy or that EA is necessary.

Eight case pairs, one deterministic execution per arm/case, fresh Episode and policy state. Six primary worlds are copied exactly from C3 seeds RA01/RA03/RA05/RQ01/RQ03/RQ05. A-S and Q-S intentionally overlap; they are not independent evidence. Two separately labelled development boundary worlds derive from RA01: B-ACQUISITION revokes transition at tick 27 and renews at 50; B-DEADLINE changes only the deadline to 34. Frozen C3 code and fixtures remain unchanged. Neither boundary is a withheld or historical case.

All worlds, task obligations, initial observations, source access, native guards, clocks, outcome oracle, tool budgets and policy rules are identical within each pair. The only intended arm difference is EA computation/signalling and its consumption. Model, tokens, humans and API calls are absent in both. The receiver receives only initial public view, actual tool responses and (EA arm only) delivered signals. World, expected outcome, case ID, future schedule and oracle are held by the runner/evaluator. This is a code boundary, not a security sandbox against a hostile host.

## Fixed competent conventional policy

Each cycle queries authority, applicability and reports through the unchanged native tool interface. It uses the latest returned native point facts without treating them as future leases. T1 is provisionally eligible only with current returned transition/access true, Q true and at least two qualified, nonrevoked, unexpired declared roots. These observations do not bypass commit/request/effect-time native guards. A peer instruction is never authority or evidence. The legitimate required deliverable is public; if it is T0 the policy completes T0 even if T1 is inadmissible. If T1 is required but not eligible, it waits five logical ticks and resamples. Guard rejection or a blocked inspection causes the same re-entry. On success it calculates the sum from returned integers and submits; the native completion checker must accept it. There are no seed/case-specific branches or future renewal times in the policy.

## EA intervention and consumption

The EA arm uses the exact published v0.2 adapter and temporal comparator, with v0.1 qualification. Every cycle the host records signal computation, emission, receipt and the policy decision referring to that signal ID. The initial previous snapshot uses only initial reports, with no fabricated point checks. A subsequent previous snapshot is the actual earlier view.

The common conventional proposal is retained, then qualified by the delivered EA signal: for T1, a contradicted basis or negative point response requires re-entry; a non-timely signal stops further work on the proposed T1 path. UNKNOWN due solely to missing source version/forward validity does not become permission and does not impose blanket refusal: the conventional proposal remains provisional and native guards decide admissibility. T0's independent authorized work is not vetoed by a T1 signal. The consumer uses these distinctions by explicit author policy. This limited projection is a declared integration profile, not admission of the whole EA architecture or a claim that null metadata satisfies the stronger interval contract.

The overlay may be redundant with competent native reasoning. Preserve ties and native success. Its redundant conclusions cannot prove a unique EA semantic effect. Different elapsed times can change sampled facts; any outcome differences must retain that timing explanation. No attention-matched third arm is run, so a differential caused by added time is not attributed to semantic superiority.

## Time, resources and stopping

Both arms start at 25, use the world's same deadline, at most 40 tool requests, eight acquisition cycles and a 10-second local wall budget per traversal. Each native call costs its existing logical tick; inspect has the existing additional effect tick. Both pay one logical response-policy tick per cycle. EA additionally pays one processing tick and one S0 transport tick per signal. These are declared costs, not measured production latency. Also record actual wall time and process CPU duration separately. No free queries or changed deadlines.

The host advances its logical clock for processing, transport and response; these are journal entries, not new C3 event types. Native code is not edited. The signal's last-useful decision boundary is deadline minus four ticks reserved for commit, inspect/request+effect and submission. Both arms require a strictly positive completion margin before starting that sequence. Early closure disables further actions; no background work is permitted. A timeout/error is retained as infrastructure interruption, never an operational pass. Stop on legitimate checked completion, insufficient remaining time, declared budgets or closed environment. No retry of a whole traversal after seeing an undesirable result.

## Outcome and sufficiency assessment

The frozen C3 oracle scores the independently captured native trace, not the policy's assertions. Separately retain accepted submission, actual completion time, attempt/effect violations, guard denials, polls, signals, costs, signal timing and closure. The runner must verify the recorder hash chain, signal lifecycle, decisions and source call ledger. Publish every pair even when an arm fails.

| Condition | Bounded executable evidence | What this lot cannot close |
|---|---|---|
| T1 | Public observation boundary; authority/Q/report distinctions; resampling after guard denial and observed recovery. The acquisition-change case tests stale observations against unchanged guards. | Complete material-break detection, hidden change, general ecosystem coverage or H5/H6 window optimality. Primary negative cases changed before resume and cannot show detection of their onset. |
| T2 | Recorded raw-input or signal receipt, explicit proceed/wait/stop disposition, and native ownership of authorization. UNKNOWN and T1/T0 scopes remain distinct. | A model understanding/obeying the signal, external-owner handoff or all S1–S14 semantic obligations. |
| T3 | C3 authorization/justification predicates, allowed action set and native guard/completion events. | Universal per-state PNI, real-world externalities or a proven downside bound over all admissible states. |
| T4 | Completion before the fixed deadline and within declared resources, with added EA processing/transport cost visible. B-DEADLINE can expose a continuity loss from that burden. | Real-time production calibration or minimum-resource optimality. |

T1–T3 are reported as partial bounded evidence, with violations where observed. T4 is met or not met for this declared task/budget. Overall `registered_task_pass` requires the C3 operational pass, checked completion, positive margin and a valid ledger. It is **not** a declaration that the complete canonical T1–T4 conditions or EA requirements are proven sufficient. No blanket HOLD earns a pass; the legitimate task must complete.

## Freeze, checks and reporting

Expected task outcomes are frozen for development checking: both arms complete all six primary cases; both complete B-ACQUISITION; native completes B-DEADLINE while the charged EA path lacks margin. These are test expectations, not forced runtime results. No implementation or expectation changes after the registered run without a new version and preserved failure. The candidate receives none of these labels.

Before publication, compile/import checks may run but no traversal is executed. Each execution writes registration with exact code, world and dependency hashes before any policy decision. All journals, source views, signals, native traces and oracle results are retained. A separate verifier replays the oracle and checks event/ledger consistency. Deterministic repetition is a reproducibility check, not another statistical sample. Frozen inputs are public development data; hashes alone do not establish blinding.
