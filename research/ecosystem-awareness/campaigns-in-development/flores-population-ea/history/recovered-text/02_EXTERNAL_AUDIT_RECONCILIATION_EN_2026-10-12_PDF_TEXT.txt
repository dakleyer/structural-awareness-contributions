3. Repaired evaluator: what is actually tested
05_tools/validate_and_score.py --check validates casebook/session isolation and vocabulary consistency only.
05_tools/test_scoring_regressions.py runs eight narrow regression checks: reasons/sources counted before
completeness, profile mismatch, human-reviewed process strings, non-scored scope strings, access-log requirement,
frozen-oracle missing-reason negative, metadata-only source A restriction, and isolated packets. Their success cannot
be cited as EA compliance, R3 detection, scientific semantic correctness or an executed benchmark.

The response schema requires source/role process, question, time frame, justification, preserved scope, changed basis,
action owner, continuation explanation, source atoms, input_profile_used, and a trace ID. The scorer checks self-
asserted provenance consistency; the auditor must inspect actual traces. No provisional expectation is promoted to a
score until an independent adjudicator explicitly freezes it; method roles remain human judged.

The seven test cases live in 03_protocol/auditor_only/ONE_CASE_SESSION_PACKETS/, not in the candidate-facing
generic ZIP. An independent protocol runner must provide exactly one to each new session. This is also how the
indistinguishable-world negative control avoids case-pair leakage. The full ZIP is auditor-facing and contains private
proposed expectations; never distribute it to candidates as a blinded test pack.

4. What the revised package still cannot claim
There is no actual post-Flores-stage1 exogenous incident, and no demonstrated loss of independence after an initially
empirically established independent regime. CTGT 1.0→1.1 is authored source history, not an externally verified future
t1. The latest published Flores exercise is a static scripted method demonstration, not a real heterogeneous judge
network continuously monitoring B/C/D. Not every cross-version condition is C: a characterized version or binding check
is B. None of this can be overcome by adding cases to a spreadsheet.

To obtain a valid later R3, an owner and an independent assessor must preregister a currently qualified t0 reliance basis,
a legitimate externally observable t1 event, the exact receiving claim, affected scope, native data availability, finite
resources, positive continuity, null action and adjudication criteria. To attribute a distinct EA mechanism rather than
standard version/lineage monitoring, B2 must be strong and equally resourced. The A25 X1–X7 family-admission route
remains uncompleted and not applicable as a claimed pass unless a concrete base kernel and mapping are
registered.


5. Auditor verdict requested
The independent auditor should report independently on: (a) whether the revised Challenge has a meaningful material-
requirement test; (b) whether each case is rooted in correct native facts or explicitly hypothetical controlled facts; (c)
whether the expected outcome and role are independently justified and frozen; (d) whether a strong conventional peer
can satisfy it; and (e) which selected EA S/T requirements, if any, are supported at specification level. Passing the tool
tests is not one of those verdicts.

Prepared result: audit issues reconciled with caveats. Unprepared result: no EA PASS, no B2/EA DIFFERENTIAL, no
