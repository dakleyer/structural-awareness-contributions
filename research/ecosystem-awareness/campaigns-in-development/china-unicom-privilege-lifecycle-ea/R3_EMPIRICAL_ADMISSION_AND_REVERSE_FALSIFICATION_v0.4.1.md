## 1. The central correction in one sentence

**The subject of observation is not “the edge changed, therefore the rule says disallowed.” It is whether a frozen competent restoration controller *receives or can legitimately acquire*, correctly qualifies and acts on the material change in time, under a separately owner-approved policy and a declared visibility/telemetry model.** If the policy permits isolation, if evidence is inaccessible, or if native R2 already handles it, those are valid findings.

## 2. Separate policy premise from measurable outcome

**P-CONTEXT (normative/test-oracle premise, not a discovered theorem):** At the outset, an accountable source-owner chooses a rule of current isolate(R) applicability, with conditions/exception precedence, materiality and permissible actions. A true S→R edge alone does not establish that isolate(R) is unauthorized.

**H-OBS-R3 (testable, primary):** When the policy-material context changes after suspension, the **same defended, fully frozen** R2 qualifies the changed or insufficient evidential basis according to its actual allowed observations/queries; updates the decision where justified; avoids both unsupported full restoration and avoidable global HOLD; and reaches an authorized disposition within declared time and total cost.

Predeclare and distinguish **world truth**, **source-generated observational footprint**, **packet delivered/queried by each arm**, **source PDP decision**, **PEP effect** and **independent impact**. Report detection, correct insufficiency, false continuation, false HOLD *when legitimate sufficiency is reachable*, requalification, recovery, latency, privacy and cost separately. No “out-of-sample” claim follows merely from later clock time.

## 3. A real one-edge causal intervention has an observable footprint

**Minimal causal reference:** Service S is already critical and Domain B adds **one material dependency** S→R at T2 while A1 is suspended. The **exogenous structural intervention** is only the edge. This is **not** a claim that every directly or indirectly affected telemetry/NACL/token field stays byte-identical.

**Reference fixture / measurement model (to freeze before runs):**

| Layer and record | What changes or may change | What is seen by which party |
|---|---|---|
| **W: world graph** | One directly injected edge S→R; S criticality, principal, grant and initial policy remain as defined | Evaluator-private graph truth and causal/event ledger |
| **E: source events** | Dependency-registration event, service ownership, source version, effective time, causal parent | Domain B native recorder / authorized source owner; no made-up independent witnesses |
| **O: observable footprint** | Current graph query response and potentially traffic/service telemetry, policy/NACL evidence, access logs and credential metadata *if the real mechanism causally produces them* | Per-channel visibility, scope, freshness, lag, confidence limitations and rooted lineage declared **ex ante** |
| **M: access/delivery** | Subscription, lawful query, partner-origin scoped alert, cache/expiry, cross-domain coverage | Each arm's actually permitted source access, query cost, latency and consent; no private oracle leak |
| **D: decision** | Restore predicate result, subsequent current-intent derivation, PDP disposition | Native separate receipts and owner rule |
| **A: effect** | PEP attempted/permitted isolation, actual impact on S and legitimate unaffected actions | Independently inspected target state if executable; otherwise **Stage A specification-level outcome only** |

**Causal constraint:** A second *independently manipulated* NACL/policy/credential rule is a **different multivariable challenge** and cannot be pooled into the primary one-edge causal estimate. A natural downstream footprint of the edge should be **retained and accounted for**, not artificially deleted to make recognition hard. A graph event that is completely outside everyone's lawful evidence access cannot be “detected” by any arm; report identifiability. A synthetic observation-mask case is a declared **epistemic conformance test**, not a real deployment demonstration.

**Minimal prospectively frozen channels:** for each native source name: owner, semantic field, causal derivation/independence root, effective/received times, freshness, decision-relevant scope, access constraints, latency, method of confirmation, whether absent/UNKNOWN distinguishes “not present” from “not observed”, and privacy exposure. Context producer B, receiving PDP A and evaluator must not be silently merged.

## 4. R2 rehearsal versus genuinely held-out R3

The previous v0.4 §7.2 explicitly trained/repaired R2 on **source-visible critical dependency, stale-cache and irrelevant change**. Its §8.1 then reused essentially the same mechanisms as R3-A, D and E. They are **in-sample positive/negative calibration controls**, not previously unseen stress discoveries. Merely hiding another seed of the same event family from R2 can qualify as an independent test set *within a known family*, but **not as evidence of a new uncovered mechanism**.

**Admissibility rule (binding on any later reported result):**

> R2 pre-freeze repair cases and R3 held-out cases must have an explicitly declared, non-overlapping **case identity and generation/evidence partition**. If the same family/mechanism was used to repair R2, its post-freeze replay or independent test cases are reported as **known-family/in-distribution generalization controls**, not as novel out-of-coverage challenges. A claimed new R3 stress mechanism additionally requires an owner/evaluator-registered distinct information/dependency/source topology **before observing outcomes**, with all selected attempts retained.

| Existing local ID | Classification after audit | May be scored? | What it can actually support |
|---|---|---|---|
| **R1-POS, R2-DIRECT** | Known source-owned positive and directly visible R2 repair/calibration | As dedicated controls, **not** novel R3 | Competent baseline, grant/predicate/current-intent handling. |
| **R3-A** visible edge | **KNOWN-FAMILY / IN-DISTRIBUTION CONTROL**; the visible-dependency mechanism is already an R2 repair class | As preregistered held-out instance **only if no case leakage**; no new-mechanism claim | Correct application of an established native control after freeze. |

**Novelty is not assumed for B/F/G either.** A source/lineage mechanism exposed in R2 cannot be relabeled novel merely by renaming an edge, region or source. An exploratory search for uncovered R3 may be run separately after freeze but must publish **all attempted probes, search/selection budgets and conditioning**; it is not a confirmatory population sample.

**What cannot be asserted now:** no competent R2 installed/repaired/frozen, no independent selected case family/hidden seed, no actual data rights, no owner policy, no observed result or native discovered counterexample. Therefore **NO CURRENT OUT-OF-SAMPLE R3 RESULT**.

## 6. R3-C± is conformance, not a discovery experiment

The paired W+ and W− initial packets are **identical**. For the same source policy they constrain the same initial decision. This is useful for checking a specification's evidence-to-outcome consistency, but **cannot measure differentiated world-detection effectiveness or be counted as two independent scored R3 discoveries**. The condition is almost entirely determined by the policy and visibility contract. Operational burden/recovery is a **distinct active-query experiment**, admitted only if a lawful information path is actually available and the query cost/horizon is frozen. Correct conditional HOLD without accessible information is not an error.
