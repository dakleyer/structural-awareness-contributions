#### W2 operational order and critical path

The next W2 work is intentionally ordered so the source audit has a **stopping rule** and the strongest peers are not self-configured after the fact.

**Track A — comparator-defender search starts immediately and runs in parallel.**

- seek a named defender for **B2**;
- prioritize a named defender/challenger for **PA-5**, because PA-5 is the decisive test of the compositional differential;
- where practical, identify specialists for PA-2 / PA-3 / PA-4;
- record defender identity, allowed configuration envelope and any unresolved objection before a differential run is frozen;
- a self-configured comparator may still produce descriptive evidence, but cannot support the strongest differential claim.

**PA-5 special rule.** PA-5 should be treated as a public challenge contract, not as an internal strawman. Before execution:

1. publish the allowed PA-5 mechanism/resource envelope;
2. invite explicit challenge/improvement of the arm;
3. freeze the defended configuration before the EP run;
4. pre-register that **EP losing to PA-5 is published/reported on the same basis as an EP-supporting result**.

**Track B — complexity, burden and equivalence protocol comes before the broad source audit.**

The protocol must define, before comparator optimization:

- **outcome measures and branch-specific equivalence / non-inferiority margins**;
- **burden vector:** compute/tokens, processing or elapsed steps, messages/handoffs, bandwidth, human-review demand, external calls, privacy/disclosure burden and authority/escalation demand where material;
- **complexity surface:** semantic obligations, decision gates, interface contracts, normalized policy/profile/adapter configuration units, stateful components and cross-owner dependencies;
- **accountability / reconstructability:** reviewer steps/time, source objects consulted, reconstruction error and reviewer disagreement;
- preregistered Pareto/equivalence rules for any claim of “same result with simpler accountable composition”.

Raw lines of code/configuration are not a sufficient primary complexity measure.

**Track C — B2 / PA source audit and product capability freeze.**

After Track B defines what “strong enough”, “equal burden” and “simpler” mean:

- verify PA-1…PA-5/OR against primary literature;
- verify B2 capabilities against dated primary vendor/standard sources;
- integrate **C3 product-profile refresh into this same audit** for Microsoft Agent 365, LangGraph/LangSmith, FIWARE, AWS IoT/TwinMaker, OpenAI 00G, Claude Agent SDK 00H and Stripe Radar/merchant-control 00H trajectories;
- publish a dated **capability freeze** for every material B2/product capability used in a run.

A later vendor/framework change does **not** invalidate a frozen run. It opens a new benchmark envelope/version.

**Track D — freeze v0.3-r2 only after Tracks A–C are sufficiently closed.**

Minimum freeze inputs:

- W1 traceability already closed;
- measurement/equivalence protocol frozen;
- B2/PA capability/source audit pinned;
- PA-5 contract and defender status recorded;
- ablation/interaction protocol fixed;
- continuity admission gate defined;
- positioning-specific fixture admission path defined.

### Comparative admission gate — continuity first

Valid-continuity controls are an **admission gate**, not merely a later stage. Before an arm may enter a failure branch supporting a comparative claim, it must demonstrate under a matched valid-continuity branch that it does not win by:

- blanket HOLD/containment;
- unnecessary escalation;
- manufactured uncertainty/dependency warnings;
- material nominal-outcome degradation;
- unjustified burden.

Failure of the continuity gate blocks the arm from being interpreted on the corresponding failure branch until the configuration is corrected and re-frozen.

##### Current priority — two execution lanes, without waiting for a model connection

**Scheduling update — 1 October 2026:** proceed now with requirements and executable component work that does not need Codex or a model API. Couple a concrete model receiver later. This separates dependencies; it does not relax the empirical gates below or turn author-built simulations into agent trials. “Independent of the model connection” does **not** mean independently authored, externally validated or blind.

**Lane A — available now: bounded EA contract and model-independent tests.** Start from [canonical S/T/H requirements](./baseline/00_CANONICAL_REQUIREMENTS_CHALLENGES_SUFFICIENCY_HYPOTHESES_KPIS.md), the traceability register and [causal protocol §§5–8](./baseline/00G_HF_CAUSAL_NEGATIVE_TRAVERSAL_PROTOCOL_v0.3_DRAFT.md). Do not redesign EA as the owner of authorization, enforcement or escalation.

1. **Freeze observable inputs and the semantic output contract.** Use the protocol's existing fields: decision/recipient; basis/version/scope; event/source/dependencies; evidence versus instruction; sufficiency or UNKNOWN; externally grounded authority or pending verification; residual; targeted check; emission, reception and last useful time. Specify what each field can actually be derived from. Keep future events, case labels and adjudicator-only truth out of the candidate. A residual field is not a calibrated probability.
2. **Implement a bounded EA component and test its information limits.** Register expected properties from the requirements and world facts before the candidate runs. Cover legitimate unchanged operation, legitimate transition, visible authority/applicability change, source-dependence change, stale or absent evidence, and delivery after the last useful time. Include a pair of materially different worlds with identical observable input: EA cannot reliably distinguish them without an additional observation. UNKNOWN must not be scored as successful detection, and blanket refusal must fail legitimate continuity. The existing six C3 cells are a starting scope, not complete coverage of these cases.
3. **Separate signal quality from receiver response.** Score whether a signal is justified, preserves material distinctions and arrives in time. Then exercise explicitly stipulated consumer policies: conventional controls already suffice; a receiver uses the signal and rechecks; a receiver receives the signal but proceeds anyway. These are executable software/model tests, not observations of how an OpenAI model decides. Report conditional prevention separately from signal correctness. Give conventional controls the same eligible evidence and resource envelope; do not manufacture an EA advantage by hiding the source from them.
4. **Prepare composition contracts after the EA component.** Model basic S0 delivery separately from added incident lifecycle, human escalation and population input. Specify availability, latency, authority, failure and budget assumptions and test each addition separately, including absent/late response. A simulated human response is a fixture, not a human evaluation. Preserve an equivalent composition without EA semantics where necessity is the question.

**Step 2 — independently held-out variants and custody.** Changing variables in author-known cases is robustness exploration. A blinded claim requires the following operational record, not only a hash:

1. Name an external scenario author and a custodian in the run registration; roles may be held by the same independent person, but neither is the implementer. Record identities, independence/conflicts and permitted access. **Both appointments are currently pending.** Declare the case domain, public interface, scoring policy and permitted transformations before case selection; retain every case in the sealed lot.
2. The custodian prepares the private inputs, per-actor views, expected outcomes with rationale, case-specific adjudication data, schedule and extraction rules. Seal exact bytes with a private manifest containing each file's SHA-256, plus a fresh secret random nonce of at least 256 bits in the sealed bundle. Publish a separate commitment containing the bundle SHA-256, protocol version, opaque lot ID and an independently observable publication/timestamp reference. Do not publish low-entropy case hashes or expected answers during development. A Git author timestamp alone is not proof of publication time.
3. Publish the commitment before constructing or adapting the run-specific receiver to that lot and before any execution. Identify any pre-existing implementation and its revision honestly; do not claim a retrospective freeze before work already done. The implementation team receives only the declared public contract and separate development examples, never the reserved cases or their verdicts. Access is restricted outside the receiver's and developers' workspace; retain access and disclosure records. These are prospective custody requirements: no reserved bundle or successful blinding is claimed here.
4. Freeze candidate/native implementations, budgets, analysis and run instructions before the custodian/evaluator executes the entire lot. Deliver only the permitted temporal views to each receiver. Keep expected verdicts and future inputs hidden. Record outputs and independently captured events before adjudication; unplanned access, feedback or repair is recorded as a blinding deviation, not silently ignored.
5. After all predeclared runs, reveal the bundle/nonce and verify the commitment and file digests against the original publication, alongside access/deviation records. Hashes establish byte integrity; custody establishes restricted access, and neither proves author independence or eliminates prior model familiarity. If confidentiality prevents public release, report the independent verification route and its reproducibility limit. Cases exposed during EA testing cannot later be claimed as held out for a composition adapted from those results; reserve fresh material or freeze all candidates before any disclosure.

**Step 3 — composition under comparable resources.** EA, EA plus human escalation, EA plus incident lifecycle, and other registered additions inherit the [common-budget rule in EXPERIMENT_PROFILES §1](./baseline/fixtures/00G-HF-ORACLE-v0.3/EXPERIMENT_PROFILES.md) and the paired conditions above. Charge EA analysis, lifecycle processing, human waiting and response to the end-to-end budget; the last useful response deadline does not move to help an arm pass.

Fix the resource-comparison rule before execution. Equal budget does not mean identical realized actions or mandatory use of every resource. Human competence, authority and availability are explicit intervention properties, not interchangeable with an arbitrary token allowance. Where the additional component also receives extra time, information, permissions or resources that cannot be matched under the registered comparison, report the result as **composition plus additional resources**, with incremental cost; do not attribute a same-budget advantage to the component alone. Keep the task and independently defined success criteria unchanged. Add one component at a time and predeclare relevant interaction contrasts; for an EA-necessity claim within a composition, include the same composition without EA semantics. None of these additions is assumed necessary before observation.
